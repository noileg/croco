# クロコ本体

Notion + Gemini + Claude Code による個人用ワークフロー自動化パイプライン。
設計の意図・経緯は `クロコ_仕様書_統合版.md` を参照（そちらが正、本書は使い方）。

## AIに書かせないもの

**自己推薦書・志望理由書・出願書類・大学のレポートなど、本人の名義で提出する
文書をAIに書かせることはしない。** これはこのプロジェクトの設計上の前提であり、
仕組みとして守らせている。

- 捕捉の段階で「本人名義の文書」に分類されたものは**自動着手の対象から外れる**
  （「要確認」に隔離され、AIが勝手に手を付けることがない）。
- 下書きの置き場は**書き込み拒否**にしてある（`croco_settings.json` の deny）。
  指示や約束ではなく、権限として書けない。
- AIに頼めるのは**要件の整理まで**。字数上限・締切・必要書類といった、
  提出物そのものではない情報に限る。
- 併用する[下書きエディタ](https://github.com/noileg/Twitter-like-char-counter)は
  **本人が自分で書くための道具**。文字数を数えて上限の超過を色で示すだけで、
  文章を生成する機能は持たない。

この線引きは仕様書2.5章-8で確定した内容で、以降の実装はすべてこれを前提にしている。

## 動作の流れ

```
スマホ（Notion AIチャット）
    │  「未処理置き場のサブページにメモを作って」と指示
    ▼
Notion「未処理置き場」の子ページ          ← 存在すること自体が「未処理」の印
    │
    │  ▼ PC起動時に run_croco.py が走る
    │
    ├─ 捕捉フェーズ（croco/capture.py）
    │    Gemini が話題の切れ目で分割（要約はしない・逐語転記）
    │    → Inbox DB に登録
    │    → 成功したものだけ「処理済み置き場」へ移動
    │
    └─ 実装フェーズ（croco/dispatch.py）
         Inbox DB から1件選ぶ（「処理中」を「未処理」より優先。複数なら選択できる）
         → クロコを対話モードで起動（パーミッションは自動承認）
         → クロコが croco_cli.py 経由で進捗を書き戻す
         → 終了後、使ったトークンを記録
         → 上限（既定3件）まで次のアイテムへ続ける
         → まとめを出す
         → 「要確認」を今ここで話すか聞く（相談フェーズ・任意）
```

失敗したものは**何もせず放置する**のが基本方針。放置すれば次回のPC起動時に
自然に再試行されるため、専用のクラッシュ復旧処理を持たない。

## 必要なもの

- Python 3.10 以上（外部パッケージ不要。標準ライブラリのみで動く）
- Claude Code CLI（`claude` が PATH にあること）
- Notion Integration のトークン
- Gemini API キー

外部パッケージに依存させていないのは、PC起動時に走らせる都合上、
pip や仮想環境の状態で起動が失敗する余地を無くすため。

## セットアップ

### 1. 設定ファイルを置く

```
mkdir %USERPROFILE%\.croco
copy .env.example %USERPROFILE%\.croco\.env
```

`.env` を開き、`NOTION_TOKEN` と `GEMINI_API_KEY` を記入する。
プロジェクトフォルダの外に置くのは、平文の秘密情報をプロジェクト内に
持ち込まないため（仕様書2章-7）。

### 2. Notion側を用意する

1. https://www.notion.so/my-integrations で Integration を作成し、トークンを取得
2. Notion上に親ページを1つ作る（例：「クロコ」）
3. **その親ページだけ**を Integration に接続する
   （ワークスペース全体に接続しないこと。鍵が漏れた場合の被害範囲を絞るため）
4. 置き場ページとInbox DBを作る：

```
python setup_notion.py <親ページのURL>
```

表示された4行を `.env` に貼る。その後、案内に従って
Inbox DB にカレンダービュー（フィルタ：種別＝予定）を手動で追加する。

### 3. 疎通確認

```
python setup_notion.py --check
```

### 4. 自動起動を有効にする

```
powershell -ExecutionPolicy Bypass -File launcher\install_startup.ps1
```

止めるときは `-Remove` を付けて実行する。

**先に `.env` の `CROCO_CLAUDE_COMMAND` に `claude` のフルパスを設定しておくこと。**
`claude` は永続PATH（User/Machine）に入っていないことがあり、その場合
スタートアップから起動したプロセスからは見つからない。
捕捉フェーズだけ動いて実装フェーズが毎回失敗する、という気づきにくい壊れ方をする。

`launcher\croco.bat` を編集するときは **ASCIIのみで書くこと**。
cmd.exeはバッチを実行中のコードページで読み直すため、日本語を混ぜると
`chcp 65001` との組み合わせでパースが壊れ、成功時にも `pause` が走って
コンソールが居座る。日本語の出力はPython側に任せる。

## 使い方

```
python run_croco.py            # 通常（捕捉 → 実装）
python run_croco.py --capture  # 捕捉のみ
python run_croco.py --dispatch # 実装のみ
python run_croco.py --dry-run  # 書き込まず、何をするかだけ表示
python run_croco.py --headless # 対話ではなく非対話でクロコを走らせる
```

ログは `logs/croco_YYYY-MM-DD.log` に日付ごとに残る。

### 実装フェーズの動き

着手できるアイテムが複数あるときは一覧が出て選べる。
ただし起動時に無人で走る前提なので待ち続けず、**60秒で先頭を自動選択**する
（`CROCO_PICK_TIMEOUT` で変更、0 で常に自動）。

そのあと**クロコが対話モードで立ち上がり、画面を引き継ぐ**。
パーミッションは自動承認なので、放っておいても勝手に進む。
横で見ていて方針を変えたくなったら、そのまま口を挟めばいい。
これが `-p`（非対話）ではなく対話にしている理由で、
非対話だと変な方向に進み始めても終わるまで介入できない。

クロコのセッションを終えると（`/exit` など）、**続けて次のアイテムに着手する**。
「やめるなら n」と聞かれるが、無人前提なので**何もしなければ進む**。

続けて走らせる上限は3件（`CROCO_MAX_ITEMS`）。`CROCO_TOKEN_BUDGET` を入れておくと
その起動で使った合計がそれを超えた時点で次に進まなくなる（アイテムの途中では止まらない）。
`CROCO_MAX_ITEMS=0` にすると実装フェーズを一切やらない。

止まる条件は4つ。**対象が尽きた／件数の上限／トークンの上限／異常終了・中断**。
異常終了で続けないのは、同じ原因で残りも失敗して試行回数だけを食う可能性が高いため。

同じ起動の中で同じアイテムを二度は処理しない。セッションを終えても「完了」に
ならなかったものは「処理中」のまま残り、並び順では最優先されるので、
除外しないと同じアイテムを延々と起動し続けることになる。

全部終わると、Inboxの現状のまとめが出る。
**「要確認」はここでしか気づけない**ので、目を通してほしい。

### 相談フェーズ

まとめの直後に「この中で今ここで話すものはありますか？」と聞かれる。
番号を選ぶとクロコが立ち上がり、**実装ではなく相談のプロンプト**で動く。
何が決まっていないかを特定して質問し、決着したら `croco_cli.py resume` で
着手キューに戻し、そのまま実装に移れる。

実装フェーズとは既定が逆で、**何もしなければ話さずに終わる**（20秒・`CROCO_CONSULT_TIMEOUT`、
0 で聞かなくなる）。着手アイテムを選ぶときより短いのは、あちらが複数候補のときだけ
出るのに対し、こちらは「要確認」が1件でもあれば出る＝ほぼ毎回出るため。
しかも全処理が終わったあとなので、待っている間は何も進んでいない。

**`resume` は保留理由を消さない。** 「なぜ人が要ったか」はそのまま仕事の性質でもあり、
戻したあとの着手でも線引き（本人名義の文書なら本文を書かない等）に使うため。
そのぶん、戻ってきたアイテムは形の上では「着手してはいけないもの」に当たるので、
実装フェーズのプロンプトに**「これは相談済みなので改めて review に回さなくてよい」**
という但し書きが自動で入る。これが無いと resume と review を往復し続ける。

### 通知音

節目で音が鳴る（`CROCO_NOTIFY=0` で止まる）。鳴るのは2つの瞬間だけ。

| 合図 | 音 | いつ |
|---|---|---|
| 入力待ち | 上がる2音（ピポ） | クロコが許可・回答を待って止まったとき／`croco_cli.py review`／相談の誘いが出る直前 |
| 全部終わった | 下がる3音（パポポ） | `croco_cli.py done`／一連の処理の最後 |

**音の向きと意味を揃えてある。** 上がる＝まだ何か要る、下がって落ち着く＝終わった。
画面を見なくても区別できる。終了音は**何かした時だけ**鳴らす（何も無い起動でも
鳴らすと雑音になり、「鳴ったら見に行く」が成り立たなくなる）。

**クロコ自身も `croco_cli.py` 経由で鳴らす。** 対話モードのクロコは作業を終えても
ウィンドウが開いたままで、本人が `/exit` するまで `run_croco.py` は
`subprocess.run()` で止まっている。つまり「1件片付いた」瞬間は run_croco.py 側からは
観測できず、`done` / `review` を書き戻すこの経路でしか鳴らせない。
`log` では鳴らさない（区切りごとに鳴ると狼少年になる）。

**作業の途中で止まったときは `croco_settings.json` の `Notification` フックが鳴らす。**
クロコが許可を求めたり質問を投げたりして本人待ちになる瞬間で、これは
`run_croco.py` からも `croco_cli.py` からも観測できない。頻度は低いので狼少年にならない。
`Stop`（応答のたび）は採らなかった。フックは音を鳴らすだけの
`python -c`（`args` 実行形式なのでシェルを介さない）で、`async` なのでクロコを待たせない。
`CROCO_NOTIFY` は `run_croco.py` が子プロセスの環境変数として渡すので、
0 にすればフックも黙る（消し方が2箇所に分かれないようにしてある）。

**ただし `--headless`（`-p`）で走らせている間、この通知は鳴らない。**
実測すると、非対話では許可待ちになっても `Notification` は飛ばず、
飛ぶのは `SessionStart` / `UserPromptSubmit` / `Stop` の3つだけだった。
対話モードで実際に鳴るかは、本物の許可ダイアログが出る場面でしか確かめられない。

`MessageBeep` ではなく `winsound.Beep` でトーンを合成している。
このPCでは `SystemQuestion` に音が割り当てられておらず**一番重要な合図が無音になる**うえ、
他の種類は全部同じwavで聞き分けられなかった。`Beep` はサウンド設定に左右されない。

保留理由が「本人名義の文書」のアイテムを選ぶと、**下書きエディタが自動で開く**
（`CROCO_EDITOR_PATH`。無ければ何もしない）。クロコはCLIなので文章を書く場所にならず、
書くのは本人・相談相手がクロコ、という分担にしているため。

エディタは**クロコの一部ではない**。単体で使える別の道具なので、
別リポジトリ（[Twitter-like-char-counter](https://github.com/noileg/Twitter-like-char-counter)）
に置いてある。クロコは `CROCO_EDITOR_PATH` の起動口（`open_md.pyw`）を呼ぶだけ。
中に取り込むと、直すたびに2箇所へ同じ修正を当てることになる。

そのエディタ側で `.md` の既定アプリにも設定できる（`setup_md_association.py`）。
本人が普段 `.md` を開くのと、クロコが下書きの場所として開くのが同じ道具になる。
起動口が見つからなければ、クロコは黙って開かないだけで先へ進む。

### 使ったトークンの記録

対話モードでは出力を横取りできないので、Claude Codeがローカルに残す
セッション記録から実際の使用量を読んでいる。
アイテムごとに Inbox DB の「トークン」列へ積み上げ、
着手アイテムの選択画面と終了時のまとめに、過去の実績と見込みを出す。

**プランの残量そのものは取得できない。** 分かるのは「実際にいくつ使ったか」だけ。
残りいくつ使えるかはクロコのセッション内で `/usage` を叩くこと。

数え方は「新しく処理されたトークン」（入力＋出力＋キャッシュ書き込み）を基準にしている。
キャッシュ読み込みを混ぜると、会話が長引くだけで際限なく膨らむうえ大幅に割安に扱われるため、
「何をどれだけやったか」の指標として役に立たなくなる。

非対話で走らせたい場合は `--headless`。こちらは進行がテキストで流れる。

### 最初の1回

いきなり無人で走らせず、まず `--dry-run` で分割結果を確認し、
次に `--capture` だけを実行してInbox DBの中身を目視することを勧める。
実装フェーズの初回も、横で見ていられるときに手動で `--dispatch` するのが安全。

## 安全対策

| 層 | 手段 |
|---|---|
| 分類ベース | 本人自身が対応すべきものは、捕捉時点で「要確認」にして自動キューに入れない |
| 行為ベース | `croco_settings.json` の deny リスト（履歴破壊・広範囲削除・外部公開・鍵の読み取り等） |
| 判定ベース | `--permission-mode auto` の内蔵判定 |
| 範囲ベース | 作業ディレクトリを `クロコ管轄プロジェクト` 配下に限定（`--add-dir`） |
| 権限ベース | Notionトークンの接続先を必要なページ・DBだけに絞る |
| 回数ベース | 同一アイテムの試行回数が上限を超えたら「要確認」に落とす |

一番上の「分類ベース」が実務上いちばん効く。Geminiが捕捉の段階で判定して
「要確認」に隔離するので、そもそも着手対象に選ばれない。対象は4種類：

| 保留理由 | 何をすればいいか |
|---|---|
| 本人名義の文書 | 自己推薦書・志望理由書など。本人が書く（下調べまでは頼める） |
| 現実世界の行動 | 取り寄せ・手続き・予約。本人が動く |
| クロコ自身の改修 | 本人が普通に Claude Code を開いて直す |
| 本人の判断 | 価値判断そのものが中身。決めてから戻す |

実装フェーズのプロンプトにも同じ線引きを書いてあるが、そちらは指示であって
保証ではないので、分類の段階で弾くことを主の防御としている。

**「要確認」に落とした側は必ず理由を残す**（Inbox DBの「保留理由」列）。
理由が同じものは対処も同じなので、終了時のまとめでは理由ごとに束ねて、
「で、何をすればいいのか」を1行添えて出す。理由の分からない山になると、
見るたびに1件ずつ「これは何で止まってるんだっけ」を思い出す羽目になるため。
クロコ側から落ちる経路（試行回数の上限／`croco_cli.py review`）にも理由が付く。

deny リストはどのパーミッションモードでも効く最後の砦なので、
`croco_settings.json` には「絶対にやってほしくないこと」だけを書く。

**書き込みの deny は `Edit(...)` で書く。`Write(...)` は効かない。**
Claude Code のファイル権限判定は `Edit(path)` しか見ておらず、`Write(path)` は
無視される（`--debug` で警告が出る。2026-07-26に実地で確認）。
`Edit(path)` が Write を含む全ての書き込み系ツールを覆うので、これ一本でよい。
`Write(...)` を並べても守りは増えず、警告で本物の警告が埋もれるだけ。

**クロコはクロコ自身を書き換えられない。** `クロコ本体/` 配下は Edit を
deny してある。deny リスト自体がここにあるので、書けるようにすると
自分の拘束を自分で外せてしまう。読むのは可能なので、改修案を出すところまではできる。
クロコ自身を直したいときは、本人が普通に Claude Code を開いて直すこと。

**下書きも書き換えられない。** `クロコ管轄プロジェクト/下書き/` 配下も同様に
Edit を deny してある。自己推薦書のような本人名義の文書は本人が書くが、
**本文を書く以外の手伝いは受ける**と決めた（2026-07-25）。

| してよい | してはいけない |
|---|---|
| 下調べ、必要書類の洗い出し | 本文そのものを書く |
| 要件の整理（字数・締切・必須項目） | 書き出し例・言い換え案・清書 |
| 構成・骨子の相談 | 「こう直すといい」という文章の提示 |
| 原稿を読んで問題点を指摘する | |

指摘の内容（どこが・なぜ）はプロンプトで縛るしかないが、
**文章を書き込むこと自体は deny で物理的に止まる**ので、最悪の踏み外しは起きない。
要件メモは `下書き/` の**外**に置く（中に置くとクロコが書けない）。

書く側の道具は `プログラミング関係\Twitter-like-char-counter.html`（下書きエディタ）。
字数上限の超過を色で示し、要件ファイルを横に読み込める。保存先を `下書き/` にすれば
クロコがそのまま読める。詳細は `クロコ管轄プロジェクト/下書き/README.md`。

**設定ファイルを編集したら必ず検証すること。** `-p`（非対話）モードでは
検証に失敗した設定ファイルは*無言で無視される*ため、書き間違えると
deny リストごと効かなくなる。検証方法：

```
mkdir tmpcheck\.claude
copy croco_settings.json tmpcheck\.claude\settings.json
cd tmpcheck && claude doctor
```

`Invalid settings` が出なければ通っている。

### 止め方

実行中に異常に気づいたら Ctrl+C。クロコが止まり、そこまでのトークンだけ記録して、
**次のアイテムには進まない**（まとめは出る）。
効かなければコンソールを閉じるか、タスクマネージャーで `claude` / `python` を終了させる。
途中で止めてもステータスは「処理中」のまま残るので、次回起動時に再開される。

## ファイル構成

```
クロコ本体/
  クロコ_仕様書_統合版.md  設計と、そう決めた経緯（主文書）
  README.md             本書。使い方
  run_croco.py          エントリポイント（起動時に走る本体）
  croco_cli.py          クロコ自身が進捗を書き戻すためのCLI
  setup_notion.py       Notion側の実体を作る初期セットアップ
  test_offline.py       APIキー不要の回帰テスト
  croco_settings.json   無人実行時のパーミッション設定
  .env.example          設定ファイルの雛形
  croco/
    config.py           .env の読み込みと設定値
    httpjson.py         JSON over HTTP（リトライ・起動時のネットワーク待ち付き）
    lock.py             二重起動の防止
    notion.py           Notion API
    gemini.py           Gemini API（分割・逐語転記の指示を含む）
    inbox.py            Inbox DB のスキーマと読み書き
    capture.py          捕捉フェーズ
    dispatch.py         実装フェーズ
    consult.py          相談フェーズ（「要確認」を話して着手キューに戻す）
    notify.py           節目の通知音
    usage.py            使ったトークンの集計
    report.py           終了時のまとめ表示
    log.py              実行ログ
  launcher/
    croco.bat           起動用ランチャ（ASCIIのみで書くこと）
    install_startup.ps1 スタートアップへの登録・解除
  資料/                 本人が用意した原典。編集しない
  記録/                 決着済みの記録。普段は読まなくてよい
```
